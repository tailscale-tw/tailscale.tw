在 [PVE](https://pve.proxmox.com) LXC 容器中安裝使用 [Tailscale](https://tailscale.com/)

## 前言

Tailscale 是一個基於 WireGuard 技術的網路連線工具，可以幫你輕鬆建立安全的私人網路。Proxmox Virtual Environment（PVE）則是一個強大的開源虛擬化平台，支援 LXC 容器和 KVM 虛擬機。

在 PVE 的 LXC 容器中使用 Tailscale 需要特別設定，因為預設情況下，無特權（unprivileged）的 LXC 容器存取不到 Tailscale 需要的網路資源。本文說明如何解決這個問題。

## 背景知識

### LXC 容器簡介

LXC（Linux Containers）是一種輕量級的虛擬化技術，可以在單一主機上執行多個獨立的 Linux 系統，比傳統的虛擬機消耗更少的資源。LXC 容器分為：

- **特權容器**：容器內的 root 使用者擁有主機上的 root 權限
- **無特權容器**：容器內的 root 使用者（`uid 0`）在主機上被對應成非特權使用者，安全性更高

### Tailscale 的運作方式

Tailscale 把封包包在 UDP 裡傳送，建立通道不需要核心模組或任何特權操作。不過它需要存取 `/dev/net/tun`（TUN 裝置），而無特權的 LXC 容器通常沒有這個裝置。

## 在 PVE LXC 容器中啟用 Tailscale 的步驟

### 1. 讓容器存取 `/dev/net/tun`

以下三種方式擇一即可。

#### 方式一：PVE 網頁介面（Device Passthrough）

這是官方文件目前的主要做法：

1. 建立 LXC 容器。
2. 進入容器的 **Resources** 分頁。
3. 選 **Add** → **Device Passthrough**。
4. 在 **Add Device** 視窗的 **Device Path** 欄位填入 `/dev/net/tun`，按 **Add**。

#### 方式二：`pct set` 指令

在 PVE 主機上執行（`CTID` 換成容器 ID，例如 `112`）：

```bash
pct set CTID --dev0 /dev/net/tun
pct set CTID --features keyctl=1,nesting=1
```

第一行做的事跟方式一相同；第二行開啟容器的 `keyctl` 與 `nesting` 功能，官方文件把這兩行列在一起。

#### 方式三：手動修改容器設定檔

網頁介面沒有 Device Passthrough 的舊版 PVE（例如 Proxmox 7.0），可以直接修改容器的設定檔。假設容器 ID 為 112，就編輯 `/etc/pve/lxc/112.conf`，加入：

```
lxc.cgroup2.devices.allow: c 10:200 rwm
lxc.mount.entry: /dev/net/tun dev/net/tun none bind,create=file
```

**Proxmox 6.x 及更早**的版本用的是 `cgroup` 而不是 `cgroup2`：

```
lxc.cgroup.devices.allow: c 10:200 rwm
lxc.mount.entry: /dev/net/tun dev/net/tun none bind,create=file
```

### 2. 重新啟動 LXC 容器

改完設定後，容器要先關機再開機才會生效（如果容器原本就在執行中）。可以在 PVE 網頁介面操作，或在主機上用指令：

```bash
pct stop 112
pct start 112
```

### 3. 在 LXC 容器中安裝 Tailscale

確認容器裡已經有 `/dev/net/tun` 後，就可以安裝 Tailscale 的 Linux 套件。最簡單的方式是用官方安裝腳本，它會自動判斷發行版與版本（容器裡要先有 `curl`）：

```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

想手動設定套件庫的話，各發行版的指令可以在 [Tailscale 的套件頁面](https://pkgs.tailscale.com/stable/)找到。注意套件庫網址裡有發行版代號（例如 Debian 的 `bookworm`），要跟容器的版本一致，不要直接照抄舊文章裡的代號。

### 4. 啟動並設定 Tailscale

安裝完成後，啟動 Tailscale 服務並登入 Tailscale 帳號：

```bash
sudo systemctl enable --now tailscaled
sudo tailscale up
```

執行最後一個指令後會出現一個網址，打開它並登入 Tailscale 帳號，就能授權這台裝置。

## 常見問題

### 較舊的系統（CentOS 7 或 Ubuntu 16.x）

某些舊版 Linux 在 Proxmox 7.0 中可能還是存取不到 `/dev/net/tun`，因為這些系統的 systemd 太舊，不認得 `cgroup2`。

Proxmox 有提供這個問題的[解決指南](https://pve.proxmox.com/wiki/Upgrade_from_6.x_to_7.0#Old_Container_and_CGroupv2)。

### 不開放 TUN：使用 userspace networking 模式

如果不想讓容器存取 `/dev/net/tun`，可以改用 Tailscale 的 [userspace networking 模式](https://tailscale.com/docs/concepts/userspace-networking)。這個模式完全不需要管理權限，但效能可能略低。

userspace networking 是 `tailscaled` 的啟動選項，不是 `tailscale up` 的旗標。用 Debian、Ubuntu 或 RHEL 系的套件安裝的話，編輯 `/etc/default/tailscaled`，把 `FLAGS` 改成：

```
FLAGS="--tun=userspace-networking"
```

再重新啟動服務：

```bash
sudo systemctl restart tailscaled
sudo tailscale up
```

這個模式下，其他 tailnet 裝置連進這個容器沒問題；但容器裡的程式要主動連到其他 tailnet 裝置時，得經由 `tailscaled` 提供的 SOCKS5 或 HTTP proxy，細節見上面的官方文件。

使用 Proxmox 6.x 及更早版本的手動設定時，不開放 TUN 就是把設定檔裡的 `lxc.mount.entry:` 那行拿掉。

## 結論

完成以上設定後，就可以在 Proxmox 的 LXC 容器中執行 Tailscale，把容器安全地接上你的 Tailscale 網路。這種做法特別適合需要在多個虛擬環境之間建立安全連線的情境，例如家庭實驗室、個人雲端服務或分散式的開發環境。

不論是管理個人的家用伺服器還是企業的虛擬化環境，Tailscale 搭配 PVE LXC 容器都是靈活、安全又容易管理的做法。
